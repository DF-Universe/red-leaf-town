# 设施改良与精制策划

2026-10-05。本文记录设施改良版本的确认规则、实装数值和经济测算。内容已实现，运行时以 `data/game.json` 为准；发布与验收记录见文末。

可视化测算：[交互报告](facility-balance.html)。重跑：`../../venv/bin/python scripts/facility_balance.py --html docs/facility-balance.html`。脚本只读取本地内容配置，不访问玩家存档、不写运行时配置。

## 已确认的产品规则

- 等级上限提高到30；产业发展以已有设施改良为主题；本次不新增动物和畜栏等级。
- 固定两块农田合并为一个改良田，统一种同一种作物、统一收获；一名伙伴看整块，占一个农作编制。底层按两个单倍任务分别结算，不把一次随机结果简单翻倍。
- 居民20、24、28级各免费增加一块普通田，原始生产规模从8增加至11；全部改良后为3块双倍田和5块普通田。新增普通田不另收费，不增加农作伙伴编制。
- 首版一间精制房、六个独立产物格、一名加工伙伴，占加工编制。一次每格放一批同品质原料，不允许混合品质。原料投入扣除，精制不消耗体力。
- 精制速度随加工能力提高，时间推动品质，品质能力限制最高品质；普通原料在各品质节点的净收益率基本相同。
- 原料时间系数：普通1、良品0.8、上品0.6、臻品0.4；奇迹原料不可投入。这取代先前的0.95/0.9/0.8方案。
- 加工伙伴现有特性不作用于精制，后续通过一破第二特性扩展。现有加工减时10%天赋、体力返还天赋和生产道具不作用于精制；全局加工能力天赋与匠心品质能力生效。
- 精制房六格全部为空才能撤下或更换伙伴。任何未领取物品都占格，包括已到最高品质的成品。
- 取消时先结算到当前服务器时间：普通品出现前原数量、原品质退回原料；普通品出现后按当前品质发成品。均清空该格，不留可重复利用的进度。
- 精制居民经验为0，伙伴经验每房实际工作每小时5 XP。六格同时工作不重复乘算；到顶和普通品出现前的取消按实际工作时段计经验。
- 两口塘分别养红鲫和青鲤，不开放换养。饲料槽扩容并降低生产耗料。
- 农田合并要求原两田为空；在建设确认时选择保留的一名原驻场伙伴，其余自动撤下。允许保留为空，随后按现有流程派驻。
- UI沿用现有全局主题、卡片、弹窗和按钮。优先扩展已有组件，仅在多阶段精制状态无法由现有组件正确表达时增加必要的薄展示组件。

## 精制配方与时间

| 配方 | 同品质原料 | 产量 | 普通／良品／上品／臻品售价 | 基准最高品质耗时 |
| --- | --- | ---: | --- | ---: |
| 南瓜果脯 | 南瓜3 | 1 | 240 / 288 / 360 / 480 | 27小时 |
| 青鲤鱼干 | 塘养青鲤4 | 1 | 260 / 312 / 390 / 520 | 40.5小时 |
| 葡萄酒 | 葡萄3 | 1 | 480 / 576 / 720 / 960 | 54小时 |

南瓜果脯和葡萄酒20级精制房建成后开放，青鲤鱼干22级开放。各格不同配方可并行。开工时明确选择品质、显示相应库存，不自动把奇迹或高品质原料换进去。

A=伙伴有效加工能力+已点亮的加工全局能力；Q=A+匠心15（点亮时）。有效等级仍受一破40级及当前产业上限限制。速度η=1+A/(A+100)。Q<60最高普通，60至119最高良品，120至179最高上品，180以上最高臻品。

设C为普通原料出售价值，Pq为成品q品质售价，T4为上表最高品质基准耗时。累计节点基础时间Tq=T4×(Pq-C)/(P4-C)。实际节点秒数=ceil(Tq×3600÷η×原料时间系数)。每个累计节点分别取整，不累计阶段舍入误差；达到不可达品质的时间不下发为可继续成长目标。

| 配方 | 普通累计小时 | 良品累计小时 | 上品累计小时 | 臻品累计小时 |
| --- | ---: | ---: | ---: | ---: |
| 南瓜果脯 | 7.363636 | 11.290909 | 17.181818 | 27 |
| 青鲤鱼干 | 11.25 | 17.1 | 25.875 | 40.5 |
| 葡萄酒 | 14.727273 | 22.581818 | 34.363636 | 54 |

基准是普通原料、η=1。实际代码应使用配方基础参数计算，不把本表显示截断值当精确配置。材料、能力、天赋效果、售价预览依据和品质时间点在开工时冻结；伙伴升级或热更不改变旧批次。取消或领取重复提交时不能重复发料或发成品。

精制不使用现有随机品质公式，不调用加工特性阶段，不接受生产道具。成品到顶后不变质，但占格锁人，直至领取或中断。

经验以房间至少一个格仍在有效制作/提质的时间区间并集计算，每720秒1 XP。不到720秒的余数持久化，取消不清零；空房和全部到顶的时间不累积。房间换人时先结算旧伙伴；不足1 XP的工作时间仍归原伙伴，不转移给新伙伴。实装按伙伴保存余数归属，避免零碎换人转移经验。

## 双倍田特性和道具审阅

两份子任务在同一事务同时创建，使用同一作物、伙伴、天气和开工时刻；各自保存输入、效果和结果快照，各自抽随机结果。结果按item_id和品质合并展示，一次性领取两份；每个子任务只发一次经验和奖励。

| 当前特性 | 双倍田处理 |
| --- | --- |
| 丰饲田 | 两份任务分别检查fodder标签并各加1，不对合并结果只加1 |
| 雨庭、厚土藏锋、循时而作 | 每份使用自己的相同开工上下文，品质加成各算一次 |
| 阴翳作业、暖土催生 | 两份分别按相同天气算时间 |
| 乘风播绒 | 两份分别加产量和减时 |
| 随侍在侧 | 先对每份产量上下限乘1.1并按旧规则取整，再汇总；不能对总产量乘1.1 |
| 精耕细作 | 每份各重投一件，取较高品质，共两次机会 |
| 鬼火精制、星落 | 两份分别以30%/20%独立判定升级最低品质一件；不是一份结果判定后翻倍 |
| 果树栽培 | tree_fruit任务各自+1产量并减时，葡萄不因名字带果实就继承该标签 |

新作物标签与配方必须一并审查。以上是静态规则审阅，不是双倍田实现的集成测试结果。

开工道具选择后两份子任务各消耗1件，共需2件；不足2件则整个操作拒绝，不自动只作用一半。进行中道具同样作用于两份子任务并消耗2件，先校验两份均可使用，防止一个合并卡片出现不同完成时间。种子、体力不足时整笔回滚。取消种植沿用单田规则分别处理，保持一次操作。

## 实现顺序和验收

1. 内容定义、领域计算和存档迁移：新增建设进度、双倍田映射、精制房状态。存档schema33升级至34，旧任务快照保留，所有新建设默认未建，不批量修改玩家存档。
2. 建设、投料、领取、中断和换人用例：统一校验编制、跨产业派驻、材料、等级，旧生产先结算，再变更参数。精制房非空的限制必须覆盖所有跨产业调动入口，不能只禁前端按钮。
3. 精制与双倍田独立结算测试，补鱼种限制和饲料共享预算测试；现有普通生产不得回归。
4. 复用组件接入UI，在1440、768、390、320宽度检查；长名字、六格不同阶段、最高品质未领、负净增值、材料不足、重复请求均覆盖。
5. 全量后端测试与前端类型/构建检查，再验证迁移存档和内测路由。上线时沿用现有构建脚本与chiyuki重启流程；实际执行记录见下。

必要验收场景：

- 双倍田两颗种子和两份体力原子扣除；两次独立品质/特性判定；并发领取、中断、建设不重复奖励；普通田与已开工旧田兼容。
- 精制在每个品质时间点前1秒、恰好该秒、后1秒的判断；低品质能力停在自身上限；六格不同开工时间和不同快照。
- 普通品出现前取消退原品质原料；出现后取消给当前成品；重试不能同时退料和给成品。
- 到顶未领仍锁伙伴；房间全部清空才可调动；仅一格工作与六格工作经验一样；多次读取、取消、隔天离线、换人不重复计算时间。
- 伙伴升级、新增天赋、配方热更不追溯旧批次；精制不能触发加工特性、返还体力、生产道具或奇迹品质。
- 两塘只接受对应鱼苗；新槽节料与畜牧/鱼塘同时结算、空槽停摆、配种一次性扣料无折扣；升级前后分段正确。
- 25级溢出经验自然重算；20/24/28级新增普通田对旧玩家正确补齐且幂等；合并田不被按卡片数量补回为额外土地；收费改良设施不免费赠送。

上线后继续观察真实玩家的供料、共享体力与领取频率造成的闲置收益；这些属于长期运营观测，不以离线模型替代。
